## Architecture rules (ArchUnit)

`src/test/java/dev/ericsanchez/ordersync/architecture/ArchitectureTest.java`, production classes only. All 6 pass.
Each one was broken by hand once, and only the intended rule failed:

| Rule | Violation introduced by hand | Result |
|---|---|---|
| `transform` is pure (no Spring, JPA, `java.net`, `erp`, `job`) | `@Component` on `MoneyParser`; a `java.net.URI` field in `OrderTransformer` | fails (each) |
| Controllers do not access the database: no Spring Data repository or `*Repository` / `*Queries` class, nothing from Spring JDBC (`JdbcClient`, `JdbcTemplate`, `NamedParameterJdbcTemplate`), Spring ORM, JPA (`EntityManager`), `java.sql` or `javax.sql` (`DataSource`) | a `SyncJobRepository`, a `SyncJobQueries`, a `JdbcClient`, an `EntityManager` and a `DataSource` field in `AdminJobController` | fails (each) |
| No cycles between top-level packages | an `ErpClient` field in `AppConfig` | fails |
| Money is never `double`, `float`, `Double`, `Float`, `BigDecimal` or `java.text.NumberFormat` (and subclasses such as `DecimalFormat`) in `transform`, `erp`, `webhook` | a `double` field in `ShopOrder`; a `List<BigDecimal>` in `ErpOrder`; a method returning `float` in `MoneyParser`; a call to `Math.floor(double)` in `OrderTransformer`; `NumberFormat.getInstance(Locale.ROOT).parse(s).longValue()` in `MoneyParser`; a `DecimalFormat` field in `MoneyParser` | fails (each) |
| No field injection: `@Autowired`, `@Value`, `@Inject` or `@Resource` on a field | an `@Autowired`, a `@Value("${...}")` and a `@Resource` field in `AdminJobService` | fails (each) |
| No sleeping thread in production code: `Thread.sleep`, `TimeUnit.sleep`, `LockSupport.park*` | `Thread.sleep(1)`, `Thread.sleep(Duration)`, `TimeUnit.MILLISECONDS.sleep(1)` and `LockSupport.parkNanos(1)` in `SyncWorker` | fails (each) |

`@Inject` is checked by name only: `jakarta.inject` is not on the classpath, so no violation with it could be
compiled to try the rule.

Known limits of the money rule. Floating point that leaves no trace in the class's dependencies is not seen:
- a local `double` variable that never goes through a method call or a field (`double d = cents * 1.5`); tried by
  hand, the rule does not see it;
- floating point hidden inside a library method whose own signature has none (a `String` in, a `long` out).
  `NumberFormat`, the usual JDK way of doing that, is banned by name; other libraries are not chased.

Before this rule set existed, the packages had three cycles (`config` <-> `erp`, `config` <-> `job`, `config` <->
`webhook`): `AppConfig` declared beans of those packages, which in turn read `config`'s properties. The beans moved to
`erp.ErpConfig` and `webhook.WebhookConfig` (as `stock.StockConfig` already did), and `BackoffPolicy`, shared by the
order worker and the outbox relay, moved to the neutral package `retry`. No rule has exclusions.

## Mutation testing (PIT)

Scope: the pure logic only, `transform.*` (`MoneyParser`, `OrderTransformer`, `ErpOrder`), `retry.BackoffPolicy` and
`webhook.HmacVerifier`, mutated against their unit tests only (`MoneyParserTest`, `OrderTransformerTest`,
`BackoffPolicyTest`, `HmacVerifierTest`). The integration tests are left out on purpose: each needs Postgres and
WireMock containers, and PIT runs the covering tests once per mutant. Not part of `build`; run with
`./gradlew pitest`.

|---|---|

| Killed | 79 |
| Survived | 0 |
| No coverage | 0 |
| Timed out / memory error / run error | 0 / 0 / 0 |
| **Mutation score** | **100%** (79 of 79) |

By class: `OrderTransformer` 35, `BackoffPolicy` 23, `HmacVerifier` 12, `MoneyParser` 9 (all killed). PIT's own line
coverage of the mutated classes: 89 of 98 lines. The 9 lines its unit tests do not run: the private constructors of
`MoneyParser` and `OrderTransformer` (4), the `throw` of three argument checks (`BackoffPolicy` with base > max or
attempt < 1, `HmacVerifier` with a blank secret: 3), and the `GeneralSecurityException` catch of `HmacVerifier`,
unreachable because every JDK must provide HmacSHA256 (2).

The first run of the same scope gave 66 of 79 (83.5%): 5 survived and 8 had no coverage. None was equivalent; each
pointed at a missing test, which was added:
- `OrderTransformer`: no test reached six of the validations (null order, missing currency, malformed total, blank
  SKU, malformed price, unknown customer), so "return null" mutants survived; and `quantity < 1` -> `<= 1` survived
  because no valid order had a quantity of 1. Added a table of invalid orders with their reasons and a quantity-1
  order.
- `BackoffPolicy`: `max < base` -> `<=` (base equal to max is valid), the `n > 30` shortcut -> `>=` (attempt 30 is
  still exponential when the cap allows it), the cap check `>` -> `>=` (a cap that is not a multiple, 8003 ms, was
  rounded up), and the jitter range `+ 1` -> `- 1` (the full delay could never be drawn). Added one test for each.
- `HmacVerifier.sign()` and `MoneyParser.toCents(null)` had no unit test. Added both.

Gate: `mutationThreshold = 95`, the measured score minus 5.
