# Quality run 2026-10-15, after the operator page (H7)

Three runs on the working tree (base commit f1c751f plus the H7 changes, not committed yet): `./gradlew clean
build pitest`, then `./gradlew clean build` twice, the last one after the tester's added test. H7 adds a static
operator page under `/ops/**` (HTML, CSS and JavaScript, not measured by JaCoCo) and its own security filter chain in
`SecurityConfig`, which is the only new Java. Same environment, tools, rules and method as the [first report](20261014-quality.md). Every figure below is copied from
these runs' reports; the three runs measured exactly the same lines (the JaCoCo CSVs are identical).

Raw data in this folder: `20261015-h7-jacoco.csv` (JaCoCo's per-class counters, line endings converted to LF) and

## Tests

`./gradlew clean build`: 178 tests, 0 failures, 0 errors. The 9 new ones since the
[H6 report](20261015-h6r3-quality.md) (169 tests):

- `admin/OperatorPageTest` (4): the page is served without a key, as HTML with the password field; it carries a
  Content-Security-Policy with `script-src 'self'` and `frame-ancestors 'none'` and without `unsafe-inline` or
  `unsafe-eval`; the served HTML, JS and CSS hold neither key, and have no inline `<script>`, no `on*=` or `style=`
  attribute, and no `innerHTML`, `insertAdjacentHTML`, `outerHTML` or `document.write`; and, added by the tester,
  the API docs keep working without the page's CSP (`/swagger-ui/index.html` and `/v3/api-docs` 200, with no
  `Content-Security-Policy` header).
- `admin/PublicEndpointsProbeTest` (5 new rows): `/ops/index.html` and `/ops/ops.js` 200 without a key;
  `/opsx/index.html`, `/index.html` and `/static/ops/index.html` 401.

The JavaScript is not tested in CI. It was checked with an end-to-end Playwright (Python) pass against the
docker-compose stack, outside the repository (see the README).
